## Commands

```bash
pnpm dev          # Start dev server on port 3000, or on PORT (.env.local in a worktree)
pnpm build        # Type-check + production build (tsc && vite build)
pnpm build:standalone # Type-check + the standalone build in dist-standalone/: the site in one index.html that opens from the disk, attached to each GitHub release
pnpm size         # After a build: fails over the gzip budgets of scripts/ci/constants.mjs (home page first load, all chunks)
pnpm smoke-test [url] # After a build: checks that a deployed site, production (SITE_URL of scripts/ci/constants.mjs) without a URL, serves the pages of dist/, its robots.txt and its sitemap.xml
pnpm og-image     # Regenerates public/og-image.jpg and public/og-image-en.jpg in Chromium (Playwright), in the fonts of public/fonts/
pnpm cv           # Generates the CV of each language (public/CV - Adam Issoufi.pdf, … (EN).pdf) from the content of the site in Chromium, offline
pnpm preview      # Preview production build on port 4173, or on PORT
pnpm typecheck    # Type-check only: src/, vite/, e2e/, the configs and their specs, then scripts/ (scripts/tsconfig.json)
pnpm lint         # ESLint (eslint.config.js)
pnpm test         # Run tests once
pnpm test:watch   # Run tests in watch mode
pnpm test:coverage # Run tests with coverage; fails below COVERAGE_THRESHOLDS_PERCENT (vite.config.ts)
pnpm test:browser  # After a build: Playwright checks in Chromium that no page scrolls sideways or requests Google, that each page preloads the version of its background photo that the screen shows and downloads no other, that the timeline dots sit on its line, that each page is served at its URL in each language (`/en/…`), that the header shows its links, the GitHub and LinkedIn icons and the CV link in order on one line, and the mobile menu the icons then the CV link centered under its links, that the CV link downloads the CV of the language and the icons open the profiles in a new tab, that the project cards fill the width of their section with the same size and columns, in "Show all" and on the last page of the row, that the arrows show every project in turn, that nothing moves with reduced motion, that the header stays on the screen down to the end of the long pages, under a blurred band of its height, compact on a short screen, that the open mobile menu shows each of its links whole on a phone held sideways, scrolls when higher than the screen, keeps the page behind it still and the language toggle usable above it, that the error pages center their message over a background photo, and that every job of the Experiences page shows its period, which screen readers read once, with no decoration, under headings that skip no level
pnpm format:check # Check Prettier formatting, as the CI does
pnpm format       # Format every file with Prettier
```

ESLint uses the recommended rules of ESLint, typescript-eslint, React Hooks (with the React Compiler rules) and React Refresh. Formatting is handled automatically by Prettier via lint-staged on commit.

## Architecture

Personal portfolio SPA built with React 19 + TypeScript + Vite.

**Entry point**: `src/index.tsx` mounts to the `#welcome` DOM element.

**Routing** (`src/App/App.tsx`): BrowserRouter setup with three routes per language — `/` (Home), `/projects`, `/experiences` — and a `*` catch-all rendering the NotFound page at the requested URL, without redirecting. The URL names the language: French, `DEFAULT_LANGUAGE`, has no prefix, and every other language of `LANGUAGES` has the same routes behind its prefix (`/en/`, `/en/projects`). `UrlLanguage` (`src/App`) switches i18next to the language of the URL after each navigation, `useUrlLanguage` (`src/hooks`) reads it, and the path helpers (`localizePath`, `getPathLanguage`, `removeLanguagePrefix`) are in `src/i18n/utils.ts`. Every internal link is a `LocalizedLink` (`src/components`), whose `to` is the path in the default language, or a path built with `localizePath`, so a visitor stays in the language they browse in. The language toggle goes to the same page in the other language and stores the choice, which only the root URL reads: before the first render, `/` is replaced by `/en/` when English was stored (`resolveInitialLanguage`, `src/i18n/storage.ts`). Home is in the main chunk; the other pages are loaded with `React.lazy` on their first visit, each from its own chunk, so import them from their own folder (`../pages/Projects`), never through a barrel that would put them back in the main chunk. A Forbidden page (403) exists for content the visitor may not access. The routes sit in `RouteErrorBoundary` (`src/App`), below the header: a page that throws or whose chunk fails to load shows a translated error with a reload button, and the next navigation renders the routes again. After a navigation by link, `PageHeadingFocus` (`src/App`), inside the `Suspense` of the routes, gives the keyboard focus to the first `h1` of the new page, so every page needs one. Each route also needs an entry in `PAGES` (`src/utils/pages.ts`), which drives its metadata and the HTML file generated for it in every language at build time (`projects.html`, `en/projects.html`), with its `lang`, `og:locale`, canonical URL and `hreflang` links to its translations, rendered by `src/utils/pageHtml.ts` from the placeholders of `index.html` and the `meta` translations (`meta.noScript` fills the `<noscript>`). This is required: the build also emits a not found page per language (`404.html`, `en/404.html`, served by Cloudflare for the unknown paths of their folder), which turns off Cloudflare's single-page-app fallback, so a route without its own HTML file would return a 404 on reload. The `folder` of the entry names the page folder whose chunk that HTML file preloads (`modulepreload`), so a direct visit downloads it with the main chunk, and its `backgroundPhoto` the photo that the page shows behind it (`<Page backgroundPhoto={PROJECTS_PAGE.backgroundPhoto}>`, the single source of that photo, which each page spec checks). No HTML file preloads a photo, whose bytes would delay the scripts and fonts that the text waits for (`vite.config.spec.ts` checks it): `src/preloadBackgroundPhoto.ts`, the first import of `src/index.tsx`, so evaluated before the rest of the app, adds a `<link rel="preload" as="image">` for the photo of the page at the current URL (`getBackgroundPhotoUrl`), in the version of the screen: its portrait version on the screens of `PORTRAIT_PHOTO_MEDIA_QUERY` (`src/utils/pages.ts`), in portrait and narrower than the tablet breakpoint, the whole photo on the others, as the style of `Page` picks it, so a browser downloads only the version it shows. Until it arrives, `Page` shows under it the `placeholderUrl` of the photo, a WebP 32 px wide written as a data URL, so the page never goes from black to the photo. The status pages show `STATUS_PAGE_BACKGROUND_PHOTO`. The build also emits `sitemap.xml` (`renderSitemap`, `src/utils/sitemap.ts`), the URL of every page of `PAGES` in every language with the same translations as the `hreflang` links of its HTML file (`getPageAlternates`, `src/utils/pages.ts`), which `public/robots.txt` declares. It also emits `_headers` (`renderHeaderRules`, `vite/utils.ts`, from `HEADER_RULES` of `vite/constants.ts`), the HTTP headers that Cloudflare Pages adds to its responses by path, which it reads and does not serve: browsers keep the files of `assets/`, whose name holds a hash of their content, a year without revalidating them (`immutable`), and revalidate every other file, as Cloudflare Pages does by default, since its URL stays the same when its content changes: the HTML pages, `robots.txt`, `sitemap.xml` and the files of `public/`, the fonts included. Every file of `assets/` therefore needs a hash in its name, which `vite.config.spec.ts` checks: one changed under the same name would stay a year in browsers. The header shows the version of the build after the logo, `__APP_VERSION__`, which `vite.config.ts` reads from `package.json` (`define`, typed in `src/vite-env.d.ts`). The navigation (`NavMenu`, `src/App/Header`) ends, after the links to the pages, with the official GitHub and LinkedIn icons (`ProfileLinks`, with `GITHUB_PROFILE_URL` and `LINKEDIN_PROFILE_URL` in its `constants.ts`), which open the profiles in a new tab, then the "Télécharger CV" text link (`CvLink`), which downloads the CV of the language of the page and is named by its text. From the tablet breakpoint, the navigation is a bar of the header, where a decorative line (`Separator`, `aria-hidden`) stands between the links and the icons and another between the icons and the CV link, each item keeping 16 px on each side as the links do, and the icons are as high as the text of the links; only the language toggle floats, on the right edge of the screen, and every page keeps the `page` gutter on both sides, so the toggle may pass over its content. Below it, the open mobile menu shows the same items in the same order, centered: the links, the two icons on one row, then the CV link as a pill with a download icon, smaller on a short screen so that it stays out of the column of the language toggle above the menu. The header stays stuck at the top of the screen down to the end of every page, since `WebApp` (`src/App/App.styled.ts`) is at least one screen high (`min-height`), not one screen high, which would let it leave after one screen of scrolling; its blurred band (`::after`), fixed on the screen, has its height (`header` in the `sizes` of the theme). Up to the `short` height of the theme (`screenHeights.short`, 500 px), as on a phone held sideways, both are compact (`header-compact`, 48 px, with a smaller logo and burger), so the header takes at most 15 % of the screen. Below the tablet breakpoint, the page stops scrolling while the open mobile menu covers it (`useScrollLock`, `src/App/Header/hooks`), and scrolls again from where it was once it closes; the language toggle and the burger stay above the menu, in the row of the header, out of the inert part of the page (`useInertOutside` keeps the element holding both reachable), so the language can change while it is open; the menu scrolls when it is higher than the screen, and is compact up to the `short` height of the theme, as on a phone held sideways.

**Component conventions**: every component lives in its own folder named after it:

- `ComponentName.tsx` — the component, with JSDoc on the component and on every prop
- `ComponentName.spec.jsx` — its tests, **required** for every component, at least a render without props
- `ComponentName.styled.ts` — styled-components styles, when it has any (not documented with JSDoc)
- `index.ts` — re-export

Sub-components get the same structure in their own folder inside their parent's folder. A component shared by several sub-components of a parent sits at the root of that parent's folder. Components shared across pages live in `src/components/` (e.g. `StatusPage`, which the not found, forbidden and unexpected error pages render, or `Page`, the `<main>` landmark that every page extends with `styled(Page)` and a `backgroundPhoto` prop). A page has exactly one `<main>`, its `Page`, so nothing inside it renders another, and exactly one `h1`, visually hidden when the design shows none (as on `/projects`), with `h2` and below for its sections; each page spec checks both. A text that only screen readers read, such as a heading that the design leaves out or the word read in place of a decoration, is a `VisuallyHidden` (`src/components`, with `as="h2"` for a heading), and a decoration drawn with a character (an arrow, a dash, a chevron) is hidden from them, with `aria-hidden="true"` or, in generated content, an empty alternative text (`content: '›' / ''`, after a plain `content: '›'` for the browsers without it). Every list is a `List` (`src/components/List`), extended with `styled(List)`: a `ul` with `role="list"`, since the global style removes the bullets and Safari then stops exposing a `ul` as a list (ESLint `no-restricted-syntax` refuses `styled.ul` and `<ul>` in the other TypeScript files of `src`), and the spec of each list checks its role. A `ComponentName.styled.ts` is imported only by its own component (ESLint `no-restricted-imports` enforces it): styles shared by several sub-components go in a lowercase style module at the root of their parent (e.g. `src/pages/Experiences/timeline.styled.ts`), and styles shared by pages go in a component of `src/components/`. Props are optional by default, and components must render without crashing when a prop is missing.

**Styling and design tokens**: `src/theme/tokens.ts` holds the primitive scales (palette, spacing, sizes, font sizes…) and `src/theme/theme.ts` the semantic tokens, following the xstyled theme conventions (`colors` with `-aNN` alpha variants, `space`, `sizes`, `fontSizes`, `radii`, `shadows`, `zIndices`, `durations`, `timingFunctions`, `screens`…). Import `styled`, `css`, `keyframes`, `createGlobalStyle`, `ThemeProvider` and `th` from `@xstyled/styled-components` only, never from `styled-components` directly (ESLint and a test enforce it). Styled-components read the tokens with the `th` helpers (`th.color('accent-a55')`, `th.space(16)`, `th.radius('md')`, `th('screens.tablet')`); height breakpoints sit apart, in `screenHeights` (`th('screenHeights.short')`), since xstyled reads `screens` as widths; color names are type-checked, and `src/theme/theme.spec.jsx` checks that every token used in a style file exists. A negative space token is written `th.space(-8)`. `keyframes` have no theme context, so they read the `theme` object (`translateY(-${theme.space[12]})`), as JavaScript code (canvas, inline styles) does. A value shared with JavaScript stays a named constant, interpolated with its unit (`${BUTTON_WIDTH_PX}px`). `App` provides the `ThemeProvider` and `GlobalStyle` (which replaced `index.css`). With the reduced motion preference (`REDUCED_MOTION_QUERY`, `src/theme/constants.ts`), `GlobalStyle` plays every animation once, and starts it and every transition without delay, lasting the `instant` duration, with `!important` so that it also wins over the inline styles of the hooks; what moves in JavaScript (a `requestAnimationFrame` loop, a style that follows the pointer) reads `usePrefersReducedMotion` (`src/hooks`) and stands still, as the particle field, the cursor glow, the parallax, the magnetic buttons and the words of the home title do, and the tilt of the project cards (`useCardTilt`). Never write a raw color, spacing, size, font size, radius, shadow, duration, easing, z-index or breakpoint in a style file: look for an existing token first, then add one to the right scale. `theme.spec.jsx` fails on any length in `px`, `em`, `rem` or `ch`, duration, color, easing, or raw z-index, font weight or line height written in a `*.styled.ts` file or `GlobalStyle.ts` (`findRawValues`, `src/theme/testUtils.js`); zero, percentages, viewport units, angles and unitless numbers (scale factors, opacities, flex factors) may stay raw. `theme.ts` writes no value itself: each semantic token reads a primitive of `tokens.ts` (`radii[12]`, `easings.easeOutBack`, `shadowShapes['4-24']`), or a color built from one with `alphaVariants`, and `theme.spec.jsx` fails on a literal or a raw value written there (`findRawThemeValues`, same file). A new value therefore goes into a primitive scale first.

**Logic, constants and hooks**: magic numbers are named constants with their unit (`constants.ts` next to their users), computations are pure helpers in `utils.ts` with tests, and stateful effects are hooks in `hooks/useThing/` with tests (see `src/pages/Home/hooks`).

**Static data**: page-level data lives in `.data/*.json` files inside the page directory (e.g. `src/pages/Projects/.data/freelance-projects.json`). A text shown to visitors is not written there but named by a translation key, as the `nameKey` and `typeKey` of each project, translated under `projects.names` and `projects.types` by `translateProjects` (`src/pages/Projects/utils.ts`), so every language has its own; client names keep the same text in both files. The `id` of each project keys the visitor's like in `localStorage` (`useLikes`, `src/pages/Projects/Project/hooks`, with no count and nothing liked on a first visit): keep it an integer that no project of either file shares, which `Projects.spec.jsx` checks, and never give it to another project. The timeline of the Experiences page is data too, `src/pages/Experiences/.data/experiences.json`: its companies, roles, projects and technologies, with keys of the `exp` translations (translated by `translateKey`, `src/i18n/utils.ts`, which gives an empty text rather than the key for a missing one), rendered by `CompanyEntry` and `RoleDescription`. Add an experience there, never in the JSX: the CV reads the same file. The timeline is a list of the companies, each named by a `h2` that only screen readers read, since each card writes the company, with a `h3` per job, each in an `article`, and a `h4` per project. From the tablet breakpoint, the period column of the timeline shows the period of each job (`TimelinePeriod`), and below it the header of its card does (`JobSummary`), both with `Period`, so that it is shown, and read, once at every width.

**Link preview image**: each language has its own, `public/og-image.jpg` in French and `public/og-image-en.jpg` in English (`OG_IMAGE_PATHS`, `src/utils/pages.ts`), which every page of that language names in its `og:image` (`%PAGE_IMAGE_URL%`). `pnpm og-image` (`scripts/og-image/`) generates both from the texts of the home page in each language (`TRANSLATION_MODULES`), the theme, the web fonts, the background photo and the particle field of the home page, read through Vite, with the font files of `public/fonts/` as data URLs, so it needs no network. It runs on demand: regenerate them and commit them when one of those changes. A new language needs its path in `OG_IMAGE_PATHS` and its module in `TRANSLATION_MODULES` (`scripts/utils/constants.mjs`). The helpers that it shares with the CV script are in `scripts/utils/`: the modules of the site loaded through Vite (`loadSiteModules`), the texts of the home page, the fonts and their check in Chromium, HTML escaping and data URLs (`toDataUrl`).

**Web fonts**: the site serves its fonts itself and requests nothing from Google: never add a link to Google Fonts or to any other Google service, which `google-requests.e2e.ts` refuses. The files are in `public/fonts/`, a stable place that `pnpm og-image` reads (the CV prints in static font files of its own, see CV): `montserrat-latin.woff2` (Montserrat, a variable font drawing every weight from 100 to 900) and `saira-stencil-one-latin.woff2` (Saira Stencil One, 400), the `latin` subsets that Google Fonts served to Windows and Linux, byte for byte, with their hinting, which macOS, iOS and Android ignore, next to their licenses (`montserrat-OFL.txt`, `saira-stencil-one-OFL.txt`), served with the site. `FONT_FACES` (`src/theme/constants.ts`) declares them once, and `renderFontFaces` (`src/theme/utils.ts`) writes their `@font-face` rules, with `font-display: swap`. The `font-faces` plugin of `vite.config.ts` adds to the head of `index.html`, before `page-meta` copies it into every page, a link that preloads each file, since every page shows both fonts, then a `<style>` of these rules (`getFontFaceTags`, `vite/utils.ts`). Their URL does not change with their content, so they keep the default cache of Cloudflare Pages rather than the year of `assets/` (`HEADER_RULES`, `vite/constants.ts`). Keep the rules out of `GlobalStyle` and any styled-component: Chrome loads the fonts again each time styled-components adds a rule to its style sheet, and draws the fallback font meanwhile, which made `project-cards.e2e.ts` flaky. A script that renders a page in these fonts calls `renderFontFaces` with a `getUrl` that turns each URL into a data URL of the file, as `pnpm og-image` does. A new font needs its `woff2` file and its license in `public/fonts/`, and an entry in `FONT_FACES`: `src/theme/constants.spec.ts` checks the files and the licenses, `vite.config.spec.ts` that every generated page preloads and declares each font and names no host of Google.

**CV**: each language's CV link downloads the CV written in it, `public/CV - Adam Issoufi.pdf` in French and `public/CV - Adam Issoufi (EN).pdf` in English (`CV_URLS`, `getCvUrl`, `src/App/Header/NavMenu/CvLink`). `pnpm cv` (`scripts/cv/`) generates both from the content of the site, read through Vite: the name and the job title of the home page, the experiences of `src/pages/Experiences/.data/experiences.json`, the projects of the Projects page, the GitHub and LinkedIn profiles of the header (`GITHUB_PROFILE_URL`, `LINKEDIN_PROFILE_URL`, `src/App/Header/NavMenu/ProfileLinks/constants.ts`), and `scripts/cv/.data/cv.json` for what the site does not show (contact details, skills, education, in both languages), which the site owner keeps up to date. Chromium prints a tagged A4 PDF in the font and colors of the theme, with the print sizes of `CV_LAYOUT`. The font comes from the static TrueType files of `scripts/cv/fonts/` (`CV_FONT_FILES`, with their license, source and hashes in its README), loaded as data URLs: a variable font, such as the one of the site, would become Type 3 fonts in the PDF, whose text Preview and Safari cannot select. That folder is outside `public/`, so neither the build nor the release archive holds it. The script reads each PDF back with pdf.js (`readPdf`) and stops on a Type 3 font, a font of another family, a missing text or link, more than two pages or 500 kB (`findPdfProblems`). It writes the PDFs and the fingerprint of the content of each one (`scripts/cv/fingerprints.json`), and `scripts/cv/cvs.spec.js` fails while the site no longer gives that fingerprint, or while a PDF of `public/` lacks a text or a link of the site: after a change of a text, a data file or a page that the CV reads, run `pnpm cv`, look at both PDFs, and commit them with the fingerprints. A new language needs its URL in `CV_URLS` and its texts in `cv.json`.

**Assets**:

- Background images are served from `public/` and referenced with absolute paths (e.g. `'/projects.webp'`), always written as one whole string: the standalone build rewrites these strings into relative URLs (`'./projects.webp'`), and misses a URL built from parts (`'/' + name`)
- Each background photo of `PAGES` is at most 1920 px wide and 110 kB, and has a lighter portrait version next to it (`projects-portrait.webp`): the center of the photo in 3:4, 1000 px high, under 40 kB, and a placeholder, a WebP 32 px wide under 400 bytes written as a data URL in its `placeholderUrl`. Write the three from the original with `cwebp` (commands in the README, Background photos); `src/utils/pages.spec.ts` checks them
- SVGs are imported as React components via `vite-plugin-svgr`

**Tests**: Vitest + Testing Library. Test files are co-located with the code they test: `*.spec.jsx` for components, `*.spec.ts` for helpers and hooks, `*.spec.js` for the script helpers of `scripts/utils/`, `scripts/ci/utils/`, `scripts/og-image/utils/` and `scripts/cv/utils/` and for the JavaScript test helpers (`src/styleTestUtils.js`, `src/pages/testUtils.js`, `src/theme/testUtils.js`); the specs of the CV build its real content from `CV_SOURCES` (`scripts/cv/testUtils.js`). `vite.config.spec.ts` builds the site in memory with the real config and checks the generated pages, such as the chunk each one preloads, the sitemap and `_headers`, and `vite.standalone.config.spec.ts` does the same for the standalone build. The setup file, `src/setupTests.ts`, extends Vitest with `@testing-library/jest-dom` and wraps every `render` of Testing Library in the theme and global styles of the app (`withTheme`, `src/testUtils.tsx`), around the wrapper a spec passes, so a spec adds no `ThemeProvider` (only the specs of `src/theme` render it, to test the theme and the global styles themselves). It also gives no canvas context, and fails a test that logs with `console.error`: fix the warning (an update outside `act`, such as a page loaded with `React.lazy`, is awaited with a `findBy` query or `waitFor`), or silence an expected error with `vi.spyOn(console, 'error').mockImplementation(() => {})`. As in production, styled-components inserts each rule into the CSSOM with `insertRule` (`SC_DISABLE_SPEEDY: 'false'` in the `test.env` of `vite.config.ts`), since jsdom parses a whole `<style>` again on every change of its text, which made the suite several times slower: the `<style>` elements hold no text, so read the rules through `document.styleSheets`, with `listStyleRules` and `declaredStyle` of `src/styleTestUtils.js`, shared by the specs of every folder. `src/setupTests.ts` also fails a test whose component inserts a rule that the CSSOM refuses or that holds the source of a function (a function interpolated outside a `css` block), since browsers drop it (`logDroppedCssRules`, `src/cssRuleGuard.ts`). The CSSOM serializes a declared value as browsers do (a length of `0` as `0px`, `calc(24px - 5px)` as `calc(19px)`, `url("/a.webp")` with quotes): build an expected value from tokens with `serializeCssValue`. jsdom ignores media queries (except `all` and `screen`), does not focus an element hidden by `display: none`, converts computed lengths into pixels, and leaves out of `getComputedStyle` a rule whose selector list holds a pseudo-element (`*, *::before, *::after`): read the declared rules in those cases. jsdom decides `:focus-visible` from the last keyboard, mouse and focus events and from the last element that matched it, which it keeps for the whole file, so it may refuse it after the first Tab of a file: check what the focus shows rather than the pseudo-class. `src/setupTests.ts` runs for every spec, including the node ones: guard any DOM global it touches. jsdom has no `matchMedia`: a spec that needs a media query to match, such as the reduced motion preference, stubs it with `stubMatchMedia` (`src/mediaQueryTestUtils.ts`), and undoes it with `vi.unstubAllGlobals()`. When an AI agent runs Vitest, it hides the console output of the passing tests: add `--reporter=default` to see it. Components that need routing must be wrapped with `<BrowserRouter>` in tests. The helpers shared by the page tests live in `src/pages/testUtils.js`, in JavaScript like the specs, such as `isPublicFile`, which checks that an image URL names a file of `public/`, or `getReadText`, the text that screen readers read in an element, without its parts hidden by `aria-hidden`.

**Browser tests**: jsdom computes no layout, so what needs one is checked in Chromium by the Playwright tests of `e2e/` (`*.e2e.ts`, `playwright.config.ts`), on the production build that `pnpm preview` serves on the port of the worktree. At the URLs of each language of `LANGUAGES` (`/projects`, `/en/projects`), at 320, 375, 414 and 1440 px, `horizontal-overflow.e2e.ts` opens every route of `PAGES`, an unknown path and a long one (`LONG_NOT_FOUND_ROUTE`, percent-encoded words then a word of 64 letters), and fails when a page is wider than the screen, and `timeline.e2e.ts` opens the Experiences page, and fails when the center of a dot of its timeline is more than 0.5 px from the center of the line. `google-requests.e2e.ts` opens every route of each language, and fails when a request of the page goes to a host of Google (`isGoogleUrl`, `e2e/utils.ts`: the `GOOGLE_DOMAINS` of `e2e/constants.ts` and their subdomains, and the country domains of the search engine), or unless each font of `FONT_FACES` is loaded. In each language, on screens in portrait at 375, 414 and 799 px wide, and at 800 px in portrait, 667 px in landscape and 1440 px (`PHOTO_SCREENS`), `background-photo.e2e.ts` opens every page of `PAGES`, and fails unless it downloads one version of a background photo only, the portrait version of its own photo on the first three screens, the whole photo on the others, requested by the preload of the app (resource timing `initiatorType` `link`). `language.e2e.ts` fails unless the preview server sends each page the HTML file of its language (its canonical URL), the root opens at `/en/` once English is stored, and the toggle moves a page to its English URL, which a reload keeps. ## Conventions

- **Branches**: `main` is production, `develop` the integration and default branch. Two rulesets, _Protect develop_ (25318593, no bypass) and _Protect main (daily deploy from develop)_ (25335502), refuse direct pushes, force pushes and deletions: every change goes through a pull request with passing checks. The one exception is `main`, updated every morning by `deploy-production.yml`, which pushes its merge of `develop` with the read-write deploy key _Daily production deploy_ (private key in the `DEPLOY_KEY` secret), the only bypass actor of the ruleset of `main`. The site owner manages the key, the secret and the rulesets: never change them. Work on each ticket in its own Worktrunk worktree, on a branch named after the ticket reference (`ISF-35`, from the `ISF-` autolink to the issues). Start it with the `ticket-worktree` skill (`ticket.mjs start ISF-35`), which fetches `develop` and branches from `origin/develop`, rather than with a bare `wt switch --create`. Open its pull request against `develop` with `Closes #35`. No pull request targets `main`, not even for a release: `develop` reaches it every morning once its CI passed, so a change merged into `develop` is in production the next day.
- **Ports**: when a worktree is created, `.config/wt.toml` writes `PORT=<port>` to its `.env.local`, a port derived from the branch (10000–19999). `vite.config.ts` reads it with `getServerPorts` (`vite/utils.ts`) for both `pnpm dev` and `pnpm preview`, and `playwright.config.ts` for the preview server of `pnpm test:browser`, so read a worktree's port in its `.env.local` rather than assuming 3000. Without `PORT`, as in the main checkout, they use 3000 and 4173. A taken port stops the server with an error (`strictPort`) instead of moving it to another port, and `BROWSER=none` stops Vite from opening the browser.
- **Commits**: Conventional Commits enforced via commitlint + husky (`feat:`, `fix:`, `refactor:`, etc.). They set the next version and `CHANGELOG.md`, which release-please writes: never edit the changelog by hand, and use `feat`/`fix` only for changes a visitor of the site would notice, since those appear in it.
- **Formatting and linting**: on commit, lint-staged runs `eslint --fix` then Prettier on staged files, one after the other (`--concurrent false`, as both write the same files). A lint error stops the commit.
