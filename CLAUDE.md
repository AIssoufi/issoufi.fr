# CLAUDE.md

The rules and pitfalls of this repository that the code does not show. How the site is built, tested and deployed is in the [README](README.md) and [`docs/`](docs/): read the scripts in `package.json`, and what each one checks in the README, before running it.

## Workflow

- **Branches**: `main` is production, `develop` the default and integration branch. Rulesets refuse direct pushes, force pushes and deletions on both: every change goes through a pull request against `develop`, never `main`, which the daily deploy updates. The site owner alone manages the rulesets, the deploy key and the `DEPLOY_KEY` secret: never change them.
- **Tickets**: one Worktrunk worktree per ticket, on a branch named after its reference (`ISF-35`), started with the `ticket-worktree` skill (`ticket.mjs start ISF-35`) rather than a bare `wt switch --create`; its pull request says `Closes #35`. Bring `develop` in with a rebase and `git push --force-with-lease`, never a merge.
- **Ports**: the `.env.local` of a worktree holds its `PORT`, which `pnpm dev`, `pnpm preview` and `pnpm test:browser` use (3000 and 4173 without it); a taken port stops the server (`strictPort`).
- **Commits**: Conventional Commits (commitlint). release-please writes `CHANGELOG.md` and the version from them: never edit the changelog, and use `feat` and `fix` only for what a visitor of the site notices.

## Code

- **Components**: one folder per component: `Name.tsx` (JSDoc on the component and every prop), `Name.spec.jsx` (required, at least a render without props), `Name.styled.ts` when it has styles, `index.ts`. A sub-component nests in the folder of its parent, one shared by siblings sits at the root of their parent, one shared by pages in `src/components/`. Props are optional, and a missing one never crashes. A `Name.styled.ts` is imported by its own component only (ESLint): shared styles go in a lowercase module at the root of the parent (`timeline.styled.ts`), or in a component of `src/components/`.
- **Pages**: every route needs its entry in `PAGES` (`src/utils/pages.ts`), which generates its HTML file in each language: without it, a reload returns a 404, since `404.html` turns off the single-page fallback of Cloudflare. A page extends `Page`, its one `<main>`, with the `backgroundPhoto` of its entry, has exactly one `h1` (a `VisuallyHidden` one when the design shows none), which `PageHeadingFocus` focuses, and headings that skip no level; its spec checks the `main` and the `h1`. Import a lazy page from its own folder, never through a barrel, which would put it back in the main chunk.
- **Markup**: every internal link is a `LocalizedLink`, given the path in the default language; every list a `List`, whose role the spec of its component checks (ESLint refuses `<ul>`: Safari drops the list role of a `ul` without bullets); a text for screen readers only a `VisuallyHidden`; every link that opens a new tab a `NewTabLink`, named by its content, never by an `aria-label` (ESLint refuses `target="_blank"` elsewhere); a text in another language than the page gets its `lang`, as the `titleLanguage` of a job of `experiences.json` gives it. A decoration drawn with a character is hidden from them: `aria-hidden="true"`, or `content: '›' / ''` after a plain `content: '›'`.
- **Styles**: import `styled`, `css`, `keyframes`, `th`… from `@xstyled/styled-components`, never `styled-components`. A `*.styled.ts` or `GlobalStyle.ts` writes no raw length, color, duration, easing, z-index, font weight or line height (`theme.spec.jsx` fails): read a token with `th` (`th.color('accent-a55')`, `th.space(-8)`, `th('screens.tablet')`, and `th('screenHeights.short')` for a height, since xstyled reads `screens` as widths). Zero, percentages, viewport units, angles and unitless numbers may stay raw. Search the tokens first: a new value goes into a primitive scale of `src/theme/tokens.ts`, which `theme.ts` only reads. `keyframes` read the `theme` object, and a value shared with JavaScript is a named constant interpolated with its unit.
- **Design rules**: no font size under 12 px (`MIN_FONT_SIZE_PX`); an accent text or icon on the dark background reads `accent-foreground`, never `accent`; a state that only a background or a shadow shows gets a system color in forced colors mode (`forced-active`, `forced-icon`); what moves in JavaScript reads `usePrefersReducedMotion` and stands still, as `GlobalStyle` does for CSS.
- **Texts and data**: every text goes in both `src/i18n/fr.ts` and `en.ts`. A data file (`.data/*.json`) names its texts by translation key. Add an experience to `src/pages/Experiences/.data/experiences.json`, never to the JSX: the CV reads it. The `id` of a project keys the like of the visitor: an integer that no project of either file shares, never given to another project.
- **Logic**: a magic number is a named constant with its unit, in a `constants.ts` next to its users; a computation is a pure helper in `utils.ts`, an effect a hook in `hooks/useThing/`, each with its tests.
- **Assets**: write the URL of a file of `public/` as one whole string (`'/projects.webp'`): the standalone build rewrites it, and misses a URL built from parts. Write images with the `cwebp` commands of the README, whose sizes the specs check. Every file of `assets/` needs a hash of its content in its name: browsers keep it a year.
- **Security**: the Content Security Policy (`vite/constants.ts`) allows the files of the site only, no inline script (a JSON-LD data block is none) and no `eval`: a resource of another origin or an inline script needs a change of the policy first. Never request Google, not even for a font: the fonts are served from `public/fonts/`, and their `@font-face` rules stay out of `GlobalStyle` and styled-components, since Chrome loads the fonts again for each rule that styled-components adds.
- **Standalone build**: never make `vite.config.ts` or the app depend on `vite.standalone.config.ts`.
- **Vite configs**: Node.js loads `vite.config.ts` and `vite.standalone.config.ts` as they are (`--configLoader native`): every relative import of a module that they load, in `src/` too, names its `.ts` file, and a JSON import says `with { type: 'json' }`, or the build fails.
- **Generated files**, committed and never built by the CI: after a change of a text, a data file or a page that the CV reads, run `pnpm cv`, look at both PDFs and commit them with `scripts/cv/fingerprints.json`; after a change of the texts, the photo, the colors or the fonts of the home page, `pnpm og-image`; after a change of the logo, its font or the colors of the theme, `pnpm icons`.

## Tests

- Specs sit next to the code: `*.spec.jsx` for components, `*.spec.ts` for helpers and hooks, `*.spec.js` for the script helpers and the JavaScript test helpers. What needs a layout is tested in Chromium (`e2e/*.e2e.ts`, after `pnpm build`).
- Read [docs/testing.md](docs/testing.md) before writing a test: the setup wraps every render in the theme and fails a test that logs with `console.error`, styles are read through the CSSOM (`src/styleTestUtils.js`), jsdom has no layout nor `matchMedia`, and a browser test waits for the animations before measuring.
- Keep `data-timeline-line` and `data-timeline-dot` naming the pseudo-element that draws them. Check that a new test fails without its fix at every size it covers.
