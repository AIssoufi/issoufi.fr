# 0018. Update pnpm to 12

- Date: 2026-10-21
- Status: Accepted

## Context

The site installs its dependencies with pnpm ([0004](0004-pnpm.md)), pinned at 10.34.7 by the `packageManager` field of `package.json`. pnpm 11.0 came out on 2026-04-28 and 12.0 on 2026-08-26; the latest release, 12.14.0, on 2026-10-15. The CI installs the pinned version with `pnpm/action-setup`, in the composite action `.github/actions/setup`.

The breaking changes of 11 and 12 that touch the project:

- pnpm 11 removes `ignorePatchFailures`, which `pnpm-workspace.yaml` set to `false`: a patch that fails to apply now always fails the install.
- pnpm 12 fails a command on a setting of `pnpm-workspace.yaml` that it does not know, when the project pins a version that the running pnpm satisfies.
- pnpm 11 makes `minimumReleaseAge` default to one day; the project sets it to 7 days.
- When pnpm switches to the version of `packageManager` (`pmOnFail: download`, the default since pnpm 11), pnpm 12 records that version and its integrity in a new YAML document at the top of `pnpm-lock.yaml`. The lockfile keeps its version 9.0, and the document of the dependencies does not change. But the dependency graph of GitHub reads the first document only, so it sees no dependency, and Dependabot raises no security alert ([dependabot/dependabot-core#15904](https://github.com/dependabot/dependabot-core/issues/15904), open on 2026-10-21). Dependabot itself updates pnpm 12 lockfiles since 2026-10-20.
- The `v6` tag of `pnpm/action-setup` still points to 6.0.10, which cannot install pnpm 12: 6.1.0, released on 2026-09-05, is the first one that can.

The other changes (`allowBuilds` in place of `onlyBuiltDependencies`, `.npmrc` read for the registry and its auth only, Node.js 22 or later, git dependencies) concern settings and dependencies that the project does not have.

## Decision

In [#354](https://github.com/AIssoufi/issoufi.fr/pull/354), for [#325](https://github.com/AIssoufi/issoufi.fr/issues/325), `packageManager` goes to `pnpm@12.14.0`, `ignorePatchFailures` leaves `pnpm-workspace.yaml`, `pmOnFail: ignore` keeps `pnpm-lock.yaml` one document, the same as with pnpm 10, and the setup action pins `pnpm/action-setup@v6.1.0`.

The 7 days of `minimumReleaseAge` still apply: `pnpm add -D typescript-eslint@8.72.0`, published two days before, is refused. pnpm itself stays excluded from it, for the day when pnpm switches to the pinned version again.

## Alternatives considered

- **pnpm 11**: still patched, but one major behind, and the move to 12 would follow soon after.
- **Staying on 10**: two majors behind, without the check of unknown settings, which catches a misspelled `minimumReleaseAge`.
- **The lockfile of two documents** (`pmOnFail: download`): pnpm switches on its own, but the security alerts stay silent until GitHub reads the last document.
- **`devEngines.packageManager`**, which pnpm 11 adds and which accepts a range: the exact pin of `packageManager` keeps every machine and the CI on the same pnpm, and Dependabot and `pnpm/action-setup` read it.

## Consequences

Measured with Node.js 24.22.0, base and branch in turn, medians of three runs.

| Figure                  | Before (10.34.7) | After (12.14.0) |
| ----------------------- | ---------------- | --------------- |
| Clean install           | 1.8 s            | 0.7 s           |
| `pnpm audit` advisories | 0                | 0               |

- The install deletes `node_modules` and keeps the store of the machine warm. On the base, the pnpm 12 of the machine hands the command over to 10.34.7, as the `packageManager` field asks. The three runs range from 1.8 to 1.9 s before, 0.7 to 0.9 s after.
- pnpm no longer switches to the pinned version: a machine with another pnpm runs it as it is, so `docs/development.md` asks for `pnpm self-update` to that version. The CI is not concerned: `pnpm/action-setup` installs the exact version. [ISF-353](https://github.com/AIssoufi/issoufi.fr/issues/353) removes `pmOnFail` once GitHub reads the lockfile of two documents.
- The duration of the CI is in the pull request.
- `pnpm/action-setup` stays pinned to an exact release, which Dependabot updates.
