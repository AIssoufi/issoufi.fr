# 0026. Update Node.js to 26

- Date: 2026-11-01
- Status: Accepted

## Context

The repository follows the active LTS of Node.js: `.nvmrc` held 24, every job that runs Node.js reads it through `node-version-file`, and `.github/dependabot.yml` ignores the majors of `@types/node`, which stayed at 24.19.2, to move both together.

Node.js 26 became LTS on 2026-10-28, and 24 moved to maintenance on 2026-10-20, with support until 2028-04-30 (`https://raw.githubusercontent.com/nodejs/Release/main/schedule.json`). `packageManager` pinned pnpm 12.14.0, three minor versions behind 12.17.0.

Node.js is the runtime of the build, the tests and the scripts of the CI: the site serves static files, so no server of production runs it.

## Decision

For [#495](https://github.com/AIssoufi/issoufi.fr/issues/495):

- `.nvmrc` goes to 26, and `@types/node` to `^26.6.5` with it. In the lockfile, only `@types/node` and its `undici-types` (7.24.6 to 8.9.0) change version. 26.6.6, published on 2026-10-28, is younger than the 7 days of `minimumReleaseAge`.
- `packageManager` goes to `pnpm@12.15.0`, the latest release past those 7 days on 2026-11-01. 12.16.0 passes them on 2026-11-02 at 23:59 UTC, 12.16.1 on 2026-11-03 at 15:27 UTC and 12.17.0 on 2026-11-06 at 14:23 UTC.
- No workflow changes, the deploy included: none names a version of Node.js. The code changes neither.
- The image of Playwright that the WebKit shards run in stays as it is. It holds Node.js 24.22.1 in `/usr/bin/node`, but `.github/actions/setup` runs `actions/setup-node` inside the container, and every later step finds the version of `.nvmrc` first on its `PATH`. Run [41273941868](https://github.com/AIssoufi/issoufi.fr/actions/runs/41273941868), a throwaway workflow in the same image, by its digest, and as the same user, prints `/__t/node/26.13.0/x64/bin/node` and `v26.13.0` for a step after the setup and for `pnpm exec node`, and the binary of Playwright starts with `exec node`.

## Alternatives considered

- **Staying on 24 until the end of its maintenance**: no risk until 2028-04-30, but the project would leave the active LTS, and the step to the next one would get bigger.
- **The newest pnpm, 12.17.0, on the `next-12` tag**: `minimumReleaseAgeExclude` lists pnpm, so nothing refuses it, but the project gives a release 7 days before trusting it, and pnpm is no exception to that choice.
- **An image of Playwright with Node.js 26**: the tag follows `@playwright/test` and Microsoft chooses its Node.js, and the job does not run that one.
- **`@types/node` left at 24**: types older than the runtime hide its APIs, and Dependabot would never move them.

## Consequences

Medians of three runs of the base and of the branch in turn on one machine, with the packages already in the store of pnpm: `pnpm install --frozen-lockfile` with `node_modules` deleted, `pnpm build` and `pnpm test`. The base runs on Node.js 24.22.0 and pnpm 12.14.0, the branch on Node.js 26.13.0 and pnpm 12.15.0.

| Figure        | Before                | After                 |
| ------------- | --------------------- | --------------------- |
| Clean install | 0.6 s (0.6 to 0.6)    | 0.6 s (0.6 to 0.6)    |
| Build         | 4.6 s (3.7 to 5.1)    | 4.5 s (3.7 to 4.5)    |
| Unit tests    | 39.0 s (38.5 to 39.9) | 35.5 s (35.1 to 35.8) |

- The install and the build show no change, their runs overlap. The 7,022 unit tests take 3.5 s less, and their runs do not overlap.
- The site does not change: the 79 files of `dist/`, built by both setups on one machine, are the same bytes (`diff -r`).
- The tool cache of the runner image holds Node.js 24 but not 26 yet, so each job that runs `actions/setup-node` downloads it: 4.5 s in run 41273941868.
- The Dockerfile of the image of Playwright installs Node.js 24 today. The WebKit shards do not depend on it, and a job that runs no `.github/actions/setup` in that image would.
- `pnpm` itself does not switch to the version of `packageManager` ([0018](0018-pnpm-12.md)): a local install keeps its own version until `pnpm self-update`.
